Design Case

A complete product design system for an AI-first creative platform — signup, onboarding, dashboard, and a supporting style guide. Designed to convert new users in under 60 seconds.

👤 Mohammad Arqam Javed
🎨 Domain: Product Design
🏆 VYROTHON 2026
🏛 NUST NSTP
Design Approach
Progressive Disclosure

Eight creation modes are too much for a single reveal. The design sequences the product: auth → intent → 3-screen onboarding → personalised dashboard. Each step reveals only what the user needs right now.

Key Decision
Intent-First Personalisation

Before showing any feature, we ask who the user is. Their answer reorders the dashboard's creation modes — a marketer sees Slides & Images first; a developer sees Docs & Sheets first. Same product, different entrance.

Onboarding Philosophy
Create, Don't Teach

Screen 3 of onboarding asks the user to create something immediately. Instead of a feature tour, users leave the onboarding with an artifact they made — the strongest possible activation signal.

A/B Test Write-Up

Test: Prompt-First vs. Mode-First Onboarding Screen 3

Hypothesis: Presenting a free-text prompt box on onboarding screen 3 (Variant A, current) will outperform showing eight creation mode cards (Variant B) in driving first-content creation, because an open prompt lowers the decision overhead — users don't need to choose a mode before they start creating.

Metric
First-content creation rate within session
Expected Result
Variant A (prompt-first) achieves +12–18% higher activation vs Variant B
Why it Matters
First content creation is the strongest predictor of Day-7 retention
Secondary Signal
Track mode distribution — what do users create when given freedom?

03 Components

All interactive components used across the Creatix flow. Each variant is annotated with its use case and state rules.

Buttons
Button rules: Primary (#5B5BF5) for the single most important action per screen. Secondary for secondary actions. Ghost for navigation-like actions. Danger for destructive operations only. Always have clear hierarchy — never two Primary buttons side-by-side. Disabled state: 40% opacity, cursor not-allowed.
Inputs
Default
Focused (simulated)
Error
Please enter a valid email address.
Success
Looks good!
Input rules: Height 44px, border-radius 14px. Focus ring: 3px solid rgba(primary, 0.35). Error state shown on blur, not on keystroke. Labels are always above the input, never floating. Placeholder text is lighter than body text (--text-3).
Cards
Base card
Used for creation mode tiles, intent cards
Elevated card
Modals, popovers, dropdowns
Accent card
AI prompt bars, featured items
Card rules: Border-radius 20px (--r-lg). All cards have a 1px solid border at --border opacity. Hover state adds transform: translateY(-2px). Never use box-shadow as the primary affordance — always pair with border-color change. Mode cards use a 2px top-border accent in the mode's colour.
Badges & Chips
✨ Primary ✓ Success ⚠ Warning ✕ Danger
Badge rules: Background is 15% opacity of the semantic colour. Text is the full semantic colour. Always border-radius 100px (pill shape). Used for status, labels, and counts — never for interactive actions.
